# CONTRACT: SEOUL SHADOWS

A third-person, non-lethal stealth contract game set in a fictional night-time Seoul. You play a
freelance operative working out of a Gangnam safehouse: take contracts, find people and evidence
without being spotted, get paid, upgrade, and work towards **$1,000,000**.

Unity 6 (6000.6.6f1) · Universal Render Pipeline · Input System · AI Navigation · PC (Linux build
tested; Windows build supported, see below).

All characters, companies and events are fictional. No one is harmed: guards warn, escort or
report you; contracts can fail and be retried.

---

## Playing

| Action | Keyboard / mouse | Gamepad |
|---|---|---|
| Move / look | WASD / mouse | Left / right stick |
| Sprint · crouch · jump | Shift · Ctrl · Space | L3 · B · A |
| Interact (hold for terminals) | E | Y |
| Map | M | View |
| Pause / back | Esc | Start / B |
| Zoom camera | Mouse wheel | D-pad up / down |

**Flow:** Main menu → New game → choose an operative (Alex Morgan: speed, Daniel Cross: stealth,
Ryan Blake: intelligence, unlockable for $50,000) → choose a contract → Gangnam. The safehouse
terminal holds three pages: **Contracts**, **Upgrades** (13 upgrades, each with one measurable
effect, plus outfits) and **Finances** (balance, goal, ledger, history, districts).

**Saving:** automatic every minute, after contracts and purchases, and on quit; manual save from
the pause menu. Continue resumes where you stood. A damaged save falls back to its backup.

## Quality tiers and performance

Three tiers (Settings → Graphics → Quality). On first launch the game picks one from the GPU;
after that the player's choice is kept.

| Tier | Pipeline | Intended for |
|---|---|---|
| Low | 0.8 render scale, 1 shadow cascade, no SSAO | Intel UHD-class integrated graphics |
| Medium | Full resolution, 2 cascades, no SSAO | Iris Xe / Arc / recent Radeon iGPUs, small dedicated GPUs |
| High | 4 cascades, soft shadows, SSAO | Dedicated GPUs with 4 GB+ |

Measured with the built Linux player (`-contract-benchmark`), Intel UHD (i5-10300H), ~1080p window,
V-Sync off, Gangnam tour with the crowd:

| Tier | Average | 99th percentile |
|---|---|---|
| Low | 60 fps | 18.8 ms |
| Medium | 38 fps | 43 ms |
| High | 22 fps | 57 ms |

No garbage collections during play; GameWorld loads in ~1.2 s; ~270 MB allocated.
Occlusion culling is baked for GameWorld and the main menu.

## Building

**Linux (installed here):** `CONTRACT > Build > Build Linux Standalone (Release)`, or headless:

```
Unity -batchmode -quit -projectPath . -executeMethod Contract.EditorTools.BuildPipeline.BuildLinuxCI
```

Output: `Builds/PC/Contract_SeoulShadows_Linux/` (exit code 1 if validation or the build fails).

**Windows:** install *Windows Build Support (Mono)* for 6000.6.6f1 in Unity Hub, then use
`CONTRACT > Build > Build PC Standalone (Release)`. Not built or tested yet on this machine.

**Benchmark a build:**

```
./Contract_SeoulShadows.x86_64 -screen-fullscreen 0 -screen-width 1920 -screen-height 1080 \
    -contract-benchmark [-contract-quality 0|1|2]
```

It plays menu → operative → contract → Gangnam, tours six spots, writes `benchmark.txt` and a
screenshot to the persistent data folder and quits. It never touches the player's save.

## Testing

115 Play Mode tests (`Assets/Tests/PlayMode`), covering boot, player controller, district, NPCs and
interaction, map, contracts and rewards, menus, upgrades and saving, audio and atmosphere, quality.

```
Unity -batchmode -projectPath . -runTests -testPlatform PlayMode -testResults results.xml
```

Run **with graphics** (no `-nographics`; particle playback needs a device). Tests write saves to a
separate `Saves_Tests` folder.

## Regenerating content

Most content is generated by editor builders. `CONTRACT > Rebuild Everything` runs them in order
(about a minute):

1. Game database · upgrade catalogue · audio
2. Gangnam district → population and navmesh → map
3. Mission / terminal UI → menu scenes and HUD
4. Quality tiers → occlusion culling

Each step also has its own menu item under `CONTRACT > Setup` / `CONTRACT > World`. Edit the
builders (`Assets/Editor`, `Assets/Editor/World`), not the generated scenes, or the next rebuild
will overwrite the change. Old prototype tools are archived in `Assets/Editor/Legacy~` (ignored
by Unity).

  `PlayerCharacterApplier`; the placeholder is used until then.
